# Write a migration (TaskHub)

Follow every step in order. Do not skip the checks — the round-trip is the evidence.

## 1. Read the rules
Read `docs/database-rules.md`. It overrides anything you remember about Alembic.

## 2. Change the model, then generate the revision
1. Edit `app/models.py` (types: `DateTime(timezone=True)` for timestamps; index FK columns).
2. Make sure the stack is up: `make up`.
3. Generate the next sequential revision:
   ```bash
   make migration name=<snake_slug>      # e.g. add_task_due_at → 0002_add_task_due_at.py
   ```
   Never edit an existing file in `migrations/versions/` — the `guard_files` hook will block it.

## 3. Review the autogenerated file line by line
Autogenerate is a draft. Check and fix:
- `revision` is the new id (`"0002"`), `down_revision` the previous one (`"0001"`).
- Server defaults, check constraints and enum create/drop are present.
- It did **not** turn a rename into drop + add (data loss).
- Index and constraint names follow `ix_`, `uq_`, `ck_` conventions.
- Remove the autogenerate comments (`# ### commands auto generated ...`).

## 4. NOT NULL on an existing table
Adding a NOT NULL column to a table with rows will fail. Either:
- `sa.Column(..., nullable=False, server_default=...)`, or
- three steps in one revision: add nullable → `op.execute("UPDATE ...")` backfill →
  `op.alter_column(..., nullable=False)`.

## 5. downgrade() reverses upgrade() exactly
In reverse order. Drop indexes before columns/tables, and drop enum types you created
(`sa.Enum(..., name=...).drop(op.get_bind(), checkfirst=True)`). Never leave `pass`.

Destructive operations (`drop_column`, `drop_table`) inside `upgrade()` need a human:
stop, explain the data impact, and only add `# approved-by: <name>` after they agree.

## 6. Run the checks
```bash
make migrate-check
```
This runs the static rules (`scripts/check_migrations.py --static`) and the
**upgrade → downgrade → upgrade round-trip** on the throwaway `taskhub_migcheck` database.
Then `make test` (tests run against `alembic upgrade head`).

Fix and rerun until both are green. Do not report success on a red check.

## 7. Report
Reply with:
- **File created:** `migrations/versions/NNNN_<slug>.py` (+ model changes)
- **What it does:** one line per operation, upgrade and downgrade
- **Checks run:** `make migrate-check` → OK (paste the two OK lines), `make test` → N passed
- **Risks / needs human:** data impact, locks on large tables, anything you were unsure about
